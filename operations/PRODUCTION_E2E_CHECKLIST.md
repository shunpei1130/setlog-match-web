# set-mob 本番E2Eチェックリスト

## 目的

本番URLで、メール認証・LINE連携・参加登録・運営ペア公開・判定・連絡先開示までを、実在する2アカウントで一度だけ確認する。初期ユーザー募集前の公開ゲートとして使う。

本番の認証コード、メールアドレス、LINE識別子、連絡先、アクセストークンはこのファイルやリポジトリに記録しない。入力値は運営者の手元だけで管理する。

## 事前確認

- [ ] 本番URL `https://setlog-match-web.vercel.app/` が開く
- [ ] Neon mainのマイグレーション8件、`funnel_events`、登録関数が存在する
- [ ] Resend、LINE Login、LINE Messaging、`CRON_SECRET`、`ADMIN_EMAILS`がVercel Productionに設定されている
- [ ] LINE公式アカウントの友だち追加導線が開く
- [ ] 本番ではローカルテスト用バイパスを使わない
- [ ] 運営画面へは`ADMIN_EMAILS`に設定した運営メールだけで入れる

## 運営者本人にしかできない作業

### 1. 2アカウントを準備

- [ ] アカウントA：本人用とは別の、参加資格を満たす青学メールを用意する
- [ ] アカウントB：Aとは別の、参加資格を満たす青学メールを用意する
- [ ] A・Bそれぞれで18歳以上確認、安全ルール同意、LINE友だち追加への同意を得る
- [ ] 運営メール例外は運営確認専用であり、2人分の参加資格の代用にしない

### 2. A・Bを登録

アカウントごとに、次の順番で実施する。認証コードは受信後10分以内に一度だけ使う。

- [ ] 本番トップから登録を開始し、流入元が必要なら計測URLを使う
- [ ] メール認証コードを発行し、受信した6桁コードで認証する
- [ ] LINE Loginを完了する
- [ ] LINE公式アカウントを友だち追加し、追加状態の確認を完了する
- [ ] ニックネーム、学部、学年、性別、利用目的（友人／恋愛／どちらでも）、希望する相手の性別を入力する
- [ ] InstagramまたはLINEの連絡先を、開示に同意できるテスト用連絡先として入力する
- [ ] 登録完了後、参加状況画面で対象イベントの待機状態を確認する

### 3. 運営画面でペアを公開

- [ ] A・Bのメール認証済み、LINE連携済み、友だち追加済み、登録状態を確認する
- [ ] A・Bを同じイベントのペアとして登録する
- [ ] 実際に案内するSetlogのURLと参加コードを入力し、別ペアの値でないことを二重確認する
- [ ] 公開前に、参加者画面でペア情報・Setlog URL・コードが見えないことを確認する
- [ ] 管理画面の公開操作を行う
- [ ] 公開後、A・Bにニックネーム、学部、学年、性別だけが見えることを確認する
- [ ] 公開直後はメール、LINE識別子、Instagram／LINE連絡先が見えないことを確認する

### 4. 判定と開示を確認

- [ ] 開始時刻前は参加開始できず、開始後にだけ参加できることを確認する
- [ ] 判定開始時刻前は回答できず、開始後に回答が保存されることを確認する
- [ ] A・Bが同じ連絡手段を選んだ場合だけ、その手段の連絡先が相互に表示されることを確認する
- [ ] `continue`だけ、`none`、片方だけの希望では連絡先が表示されないことを確認する
- [ ] 公開前・ブロック・通報時にはSetlogコードと連絡先が表示されないことを確認する
- [ ] 計測画面または管理APIで、認証開始・認証完了・LINE連携・友だち追加・登録完了・判定送信のイベントを確認する

### 5. 金曜通知を確認

- [ ] 金曜21:00 JSTのCron実行後、対象者へ「明日はマッチング」の通知が1回だけ届くことを確認する
- [ ] 同じCronを再実行しても二重送信されないことを確認する
- [ ] 通知失敗時に運営者が一斉手動送信を行わず、ログを確認して原因を記録する

## Codexが証跡受領後に行う作業

- [ ] 個人情報を受け取らず、運営者が記録した成功／失敗項目だけを確認する
- [ ] 失敗した段階のコード、ログ、画面状態から原因を切り分ける
- [ ] `GROWTH_METRICS.csv`へ件数だけを記録する
- [ ] `GROWTH_100_USERS.md`のG-004と判断ログを更新する
- [ ] 再現可能な不具合は修正し、`npm test`、`npm run lint`、`npm run build`を再実行する

## 完了判定

A・Bの実在アカウントで上記の主要経路が通り、非公開条件と相互同意開示条件が確認できたら、G-004を完了にする。連絡先や認証情報そのものを証跡として共有しない。
